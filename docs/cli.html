Quick Start

三步上手

从安装到首次蒸馏，只需三步。

1

初始化配置

创建配置文件，写入 API 凭证。只需运行一次。

$ trace2skill init
2

浏览会话

查看有哪些可用会话，挑选感兴趣的 ID。秒级返回，不调用 LLM。

$ trace2skill sessions
3

蒸馏技能

对选中的会话运行蒸馏流水线，生成结构化 SKILL.md 文件。

$ trace2skill distill -s <SESSION_ID>
Setup

init — 初始化配置

trace2skill init 首次使用前运行，创建 config.yaml 和 .env

创建 ~/.trace2skill/config.yaml 配置文件和 ~/.trace2skill/.env 密钥文件。API 密钥存储在 .env 中，config.yaml 通过环境变量读取。

# 交互式初始化（会提示输入 API Key 和 Base URL）
$ trace2skill init

# 指定所有参数
$ trace2skill init \
    --api-key sk-xxx \
    --base-url https://api.openai.com/v1 \
    --fast-model openai/gpt-oss-120b \
    --strong-model openai/gpt-oss-120b \
    --source opencode

# 带代理和网络配置
$ trace2skill init \
    --api-key sk-xxx \
    --base-url https://api.openai.com/v1 \
    --proxy socks5://127.0.0.1:1080 \
    --proxy-bypass "localhost,127\.0\.0\.1" \
    --timeout 180 \
    --connect-timeout 15
选项说明默认值
--api-keyLLM API 密钥交互式输入
--base-urlLLM API 基础地址交互式输入
--fast-model快速模型（L1/L2 预处理）openai/gpt-oss-120b
--strong-model强力模型（蒸馏和合并）openai/gpt-oss-120b
--source数据源类型：opencode | chrysopencode
--proxy代理地址（如 socks5://127.0.0.1:1080）无
--proxy-bypass不走代理的 host 正则，逗号分隔无
--verify-ssl / --no-verify-ssl是否验证 SSL 证书--no-verify-ssl
--timeout请求超时（秒）120
--connect-timeout连接超时（秒）10
Core

sessions — 浏览会话 零 LLM

trace2skill sessions 纯元数据浏览，秒级返回，不调用任何 LLM

在蒸馏前先用此命令浏览可用会话，挑选感兴趣的 ID。默认只显示消息数最多、且通过质量阈值的 top 20。

# 默认显示 top 20（按消息数排序，过滤低质量）
$ trace2skill sessions

# 按项目过滤
$ trace2skill sessions -p my-project

# 只看最活跃的 5 个
$ trace2skill sessions --top 5

# 包含低质量会话（不过滤）
$ trace2skill sessions --all

# 组合使用：看某项目的所有会话
$ trace2skill sessions -p my-project --all --top 50
选项说明默认值
-p, --project按项目名称过滤（子串匹配）全部
--top最多显示 N 个会话20
--all显示所有会话（不过滤低质量）关闭

输出示例：

Sessions (5/42)
 #  Session ID           Title                             Project         Msgs  Tools  Date
 1  abc123-def456-789...  Fix Redis connection timeout     my-project       28     12   2026-05-04
 2  xyz789-abc456-123...  Implement JWT refresh token      my-project       22      9   2026-05-03
 ...

Use 'trace2skill distill -s <ID>' to distill a specific session.
Core

distill — 蒸馏技能 核心

trace2skill distill 从 Coding Agent 轨迹中蒸馏可复用技能

完整的蒸馏流水线。支持按项目、日期、单个会话过滤。可分步执行、试运行、增量处理。默认 3 个 worker 并发。

# 蒸馏全部会话（使用默认配置）
$ trace2skill distill

# 按项目过滤
$ trace2skill distill -p my-project

# 蒸馏单个会话（先用 sessions 找到 ID）
$ trace2skill distill -s abc123-def456

# 按日期范围
$ trace2skill distill --from 2026-05-01 --to 2026-05-06

# 只看预处理结果，不蒸馏
$ trace2skill distill --step 1

# 试运行：蒸馏但不写文件
$ trace2skill distill --dry-run

# 增量模式：只处理新会话
$ trace2skill distill --incremental

# 指定数据源和输出格式
$ trace2skill distill --source chrys --format knowledge_md

# 调整并发数
$ trace2skill distill -w 5

# 强制串行 + 详细日志（调试用）
$ trace2skill -v distill -w 1 -s abc123
选项说明默认值
-p, --project按项目名称过滤（子串匹配）全部
-s, --session指定要蒸馏的单个会话 ID全部
--from起始日期（格式 YYYY-MM-DD）不限
--to截止日期（格式 YYYY-MM-DD）不限
--step执行到步骤 N 后停止：
1 = 仅预处理
2 = 蒸馏（不合并/写入）		全部步骤
--dry-run仅展示蒸馏规则，不写入文件关闭
--incremental仅处理上次运行之后的新会话关闭
--source覆盖数据源：opencode | chrys读配置
--format覆盖输出格式：skill_md | knowledge_md读配置
-w, --workers并发 worker 数3（读配置）

推荐工作流：

# 1. 先浏览，找到想蒸馏的会话
$ trace2skill sessions -p my-project

# 2. 试运行，看看蒸馏结果
$ trace2skill distill -s <ID> --dry-run

# 3. 满意后再正式蒸馏
$ trace2skill distill -s <ID>
Core

inspect — 检查会话

trace2skill inspect <SESSION_ID> 运行 L0→L1→L2 预处理，展示轨迹摘要

对单个会话运行完整预处理流水线，展示生成的摘要：类型、意图、阶段、问题、经验教训和新发现。会调用 LLM。适用于调试过滤阈值或检查会话质量。

$ trace2skill inspect abc123-def456

# 输出：
Session: abc123-def456
  Type: debug
  Project: my-project
  Intent: Fix Redis connection timeout in production
  Label: success (score: 0.85)

Phases:
  debug: Investigated Redis connection pool exhaustion
  fix: Implemented retry with exponential backoff

Problems:
  - Redis pool exhausted under load → Added connection timeout + retry

Lessons:
  - Always set connection timeout on Redis pools in production

Discoveries:
  - Redis default pool size is 10, needs tuning for high-concurrency

Fast LLM: 3 calls, 450+120 tokens

Config

config — 配置管理

查看和管理配置文件。包含 show、set、edit 三个子命令。

trace2skill config show 显示当前有效配置（API Key 脱敏）

从 ~/.trace2skill/config.yaml 加载配置，展示 Fast Model、Strong Model 和 Source 三个面板。环境变量覆盖也会反映在输出中。API 密钥仅显示前 4 个字符。

$ trace2skill config show

# 输出 Fast Model / Strong Model / Source 三个面板
Fast Model
  model: openai/gpt-oss-120b
  api_key: sk-s****xxxx
  base_url: https://api.openai.com/v1
  ...

Source
  type: opencode
  opencode.db_path: ~/.local/share/opencode/opencode.db
  chrys.sessions_dir: (auto-detect)
trace2skill config set <KEY> <VALUE> 设置单个配置项（点分路径 key）

KEY 使用点分路径格式。VALUE 为字符串值，自动转换为正确的类型（bool、int、float、str）。修改后立即生效，无需重启。

# 修改代理
$ trace2skill config set fast.proxy socks5://127.0.0.1:1080
$ trace2skill config set fast.proxy_bypass "localhost,127\.0\.0\.1"

# 调整超时
$ trace2skill config set strong.timeout 180

# 开启 SSL 验证
$ trace2skill config set fast.verify_ssl true

# 调整并发数
$ trace2skill config set concurrency.workers 5

# 修改输出格式
$ trace2skill config set output.format knowledge_md

# 修改输出目录
$ trace2skill config set output.skill_output_dir ~/my-skills

所有可用的 key 见下方可配置 Key 列表。

trace2skill config edit 用默认编辑器打开 config.yaml

使用 $VISUAL 或 $EDITOR 环境变量指定的编辑器打开配置文件。Windows 回退到 notepad，Unix 回退到 vi。

$ trace2skill config edit
# 自动用 $VISUAL / $EDITOR 打开，Windows 回退 notepad，Unix 回退 vi
Scheduling

schedule — 定时任务

管理定时蒸馏任务。包含 start 和 status 两个子命令。

trace2skill schedule start 启动定时蒸馏守护进程（前台运行）

在前景运行，按 scheduler.cron 定义的时间触发蒸馏。默认每天凌晨 3 点。使用增量策略，只处理新会话。按 Ctrl+C 停止。

# 启用调度器
$ trace2skill config set scheduler.enabled true

# 启动（前台运行）
$ trace2skill schedule start

# 查看调度器状态
$ trace2skill schedule status
调度器配置项说明默认值
scheduler.enabled是否启用false
scheduler.cronCron 表达式0 3 * * *
scheduler.strategy运行策略：incrementalincremental
scheduler.max_sessions_per_run每次最多处理会话数20
scheduler.max_cost_per_run每次最大费用（¥）1.0
scheduler.max_runtime_minutes每次最大运行时间30
trace2skill schedule status 查看调度器配置及启用状态

从 config.yaml 读取调度器设置，显示是否启用、cron 表达式和运行策略。

$ trace2skill schedule status
# 输出：Scheduler: enabled/disabled, Cron: ..., Strategy: ...
Appendix

配置文件参考

完整配置文件结构。文件位于 ~/.trace2skill/config.yaml，API 密钥存储在 ~/.trace2skill/.env。

# ~/.trace2skill/config.yaml models: fast: # 快速模型（预处理 + 聚类） model: openai/gpt-oss-120b max_tokens: 4096 api_key: "" # 推荐放 .env base_url: "" verify_ssl: false proxy: "" # socks5://127.0.0.1:1080 proxy_bypass: "" # localhost,127\.0\.0\.1 timeout: 120 connect_timeout: 10 extra_headers: {} user_agent: curl/8.0 max_rpm: 0 # 0 = 不限；每分钟最大请求数 max_concurrency: 0 # 0 = 不限；最大并发请求数 strong: # 强力模型（蒸馏），继承 fast 的缺省值 model: openai/gpt-oss-120b max_tokens: 8192 source: type: opencode # opencode | chrys opencode: db_path: ~/.local/share/opencode/opencode.db chrys: sessions_dir: "" # 空 = 自动检测 filter: min_messages: 5 min_tools: 3 output: skill_output_dir: ~/.trace2skill/skills max_rules_per_skill: 15 format: skill_md # skill_md | knowledge_md concurrency: workers: 1 # 并发 worker 数，1 = 串行 scheduler: enabled: false cron: "0 3 * * *" # 每天凌晨 3 点 strategy: incremental min_new_sessions: 3 max_sessions_per_run: 20 max_cost_per_run: 1.0 max_runtime_minutes: 30

输出目录结构

蒸馏结果按项目 + 主题组织，每个主题生成独立的 SKILL.md 文件。

~/.trace2skill/skills/ └── my-project/ ├── jwt-auth/ │ └── SKILL.md # JWT 认证相关技能 ├── redis-debug/ │ └── SKILL.md # Redis 调试经验 ├── project-setup/ │ └── project_knowledge.md # 项目级知识（knowledge_md 格式） └── api-design/ └── SKILL.md # API 设计最佳实践
SKILL.md 示例 结构化技能文件格式 
---
topic_id: jwt-auth
topic_name: JWT Authentication
session_count: 3
updated: 2026-05-06
---

# JWT Authentication

## ALWAYS
- Always set short expiry (15min) on access tokens
- Always use RS256 or ES256 for production signing

## NEVER
- Never store sensitive data in JWT payload
- Never use symmetric signing (HS256) across services

## FACT
- JWT refresh tokens should be stored in httpOnly cookies
- Token revocation requires a server-side blocklist
